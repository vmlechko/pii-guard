# Модуль безопасности ПД

Сервис-прокси в цепочке **система-потребитель → Модуль безопасности ПД → LLM**: находит
персональные данные (ПД) в тексте, маскирует их, а по повторному запросу с тем же
`payload_id` восстанавливает оригинал.

Проект готов. Контракт зафиксирован тестами, производительность измерена на реальных
нагрузках.

## Что это

Модуль встраивается между системой-потребителем и LLM. Перед отправкой текста в модель
он:

1. находит персональные данные (ФИО, телефоны, паспорта, карты, адреса и т. д.);
2. маскирует их значения;
3. сохраняет соответствие `payload_id → (оригинал, маска)`;
4. по повторному запросу с тем же `payload_id` восстанавливает оригинал (если политика
   системы это разрешает).

Горячий путь `/process` не обращается к LLM: идентификация выполняется локально
(таблица правил + быстрый regex-NER).

## Архитектура

```
система-потребитель ── POST /process ──▶ Модуль безопасности ПД ──▶ LLM
        ▲                                        │
        └────────────── результат ◀──────────────┘
```

Конвейер обработки текста:

```
текст
  │
  ▼
структурная детекция по правилам (таблица RULES)
  │
  ▼
быстрый NER ФИО / адресов (fast_ner)
  │
  ▼
фильтр по allowed_types + подтверждение bare-спанов контекстом
  │
  ▼
разрешение перекрытий (resolve_overlaps)
  │
  ▼
маскирование значений (mask_value)
  │
  ▼
идемпотентный стор оригинал ↔ маска (InMemory / Redis)
```

## Идентификация ПД

Два движка, выбираются переменной `NER_ENGINE`:

- **fast** (по умолчанию) — таблица правил + словарь имён, без внешних зависимостей;
- **natasha** (`NER_ENGINE=natasha`) — нейросетевой `NewsNERTagger` для имён и структурные
  адреса; подключается опциональным модулем `app/ner.py` с тем же интерфейсом, что `fast_ner`.

Общие принципы:

- **Таблица правил** (`detectors.py`): одна структура `Rule(regex, pii_type, priority, …)`
  и один цикл по `RULES`. Регэкспы собираются из коротких именованных фрагментов,
  ключевые слова — через общий хелпер `kw(...)`.
- **Быстрый regex-NER** (`fast_ner.py`): ФИО и адреса без маркеров-ключевых слов.
- Маскируется **только значение** ПД; служебные слова («паспорт», «серия», «номер»,
  «ул.», «д.», «кв.», «Уважаемый», «Клиент») остаются как есть.
- **Контекст отсекает ложные срабатывания**: публичные лица, адрес отделения банка,
  даты договоров, номера заказов.

Поддерживается **18 типов ПД**: 17 из ТЗ + СНИЛС (email, phone, card, cvv, card_pin,
card_holder, passport, dept_code, passport_date, passport_issuer, driver_license, inn,
snils, birth_date, birth_place, citizenship, address, fio).

## Токенизация для LLM

Перед отправкой в модель текст токенизируется: вместо значений ПД подставляются
плейсхолдеры `[FIO_1]`, `[PHONE_1]` и т. п., а соответствие `плейсхолдер → оригинал`
сохраняется в mapping. Ответ модели детокенизируется обратно. Наружу уходит только
обезличенный текст — оригиналы ПД не покидают модуль.

## Контракт POST /process

Запрос — JSON:

```json
{
  "payload": "текст с персональными данными",
  "payload_id": "идентификатор запроса"
}
```

Ответ — JSON:

```json
{
  "result": "обработанный текст"
}
```

Три ситуации (см. SPEC §1):

| Ситуация | Ответ |
|---|---|
| `payload_id` новый | маскируем `payload`, сохраняем в стор, возвращаем маску |
| `payload_id` известен и `payload == оригинал` | ретрай маскирования → та же маска (идемпотентность) |
| `payload_id` известен и `payload != оригинал` | демаскирование → оригинал (если политика разрешает, иначе снова маска) |

Заголовок `X-System-Id` (необязателен) выбирает политику системы-потребителя из
`config/systems.yaml`. Без заголовка применяется `default` (все типы, демаскирование
включено). Неизвестная или отключённая система → HTTP 403.

Дополнительно: `GET /health` → `{"status":"ok"}`, `GET /metrics` → метрики Prometheus.

### Пример с curl

Маскирование (новый `payload_id`):

```bash
curl -s http://localhost:8000/process \
  -H "Content-Type: application/json" \
  -d '{"payload": "Клиент Иванов Иван Иванович, тел. +7 916 123-45-67", "payload_id": "req-1"}'
```

Ответ — текст с замаскированными значениями:

```json
{"result": "Клиент ****** **** ********, тел. +* *** ***-**-**"}
```

Демаскирование (тот же `payload_id`, передаём маскированный текст обратно):

```bash
curl -s http://localhost:8000/process \
  -H "Content-Type: application/json" \
  -d '{"payload": "Клиент ****** **** ********, тел. +* *** ***-**-**", "payload_id": "req-1"}'
```

Ответ — восстановленный оригинал:

```json
{"result": "Клиент Иванов Иван Иванович, тел. +7 916 123-45-67"}
```

## Настройка систем

Формат `config/systems.yaml`:

```yaml
default_system: default

systems:
  default:
    name: "Базовая система"
    enabled: true
    demasking: true

  support-bot:
    name: "Чат-бот поддержки"
    enabled: true
    demasking: false
    allowed_types: [fio, phone, email, card, cvv, card_pin]
```

Параметры системы:

- `enabled` — доступ к модулю (отключённая система получает 403);
- `allowed_types` — какие типы ПД маскировать (если убрать — все 18);
- `demasking` — разрешено ли восстанавливать оригинал;
- `contextual_masking` — PIN/CVV маскируются только вместе с номером карты.

## Быстрый старт

**Docker:**

```bash
docker compose up --build
```

Сервис поднимается на портах **80** и **8000**. Вместе с приложением запускается Redis
(общий стор соответствий между воркерами).

**Локально:**

```bash
python -m venv .venv
.venv\Scripts\activate        # Windows; на Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app
```

**Опционально** — нейросетевой NER:

```bash
pip install -r requirements-optional.txt
NER_ENGINE=natasha uvicorn app.main:app
```

Демо-прокси в реальную LLM не обязателен для `/process`; его ключи и адреса задаются
через `.env` (см. `.env.example`) и в репозитории не хранятся.

## Инструкция жюри (2 минуты)

1. **Маска ПД** — `POST /process` с новым `payload_id`: ФИО, телефон, паспорт, карта
   маскируются, служебные слова остаются.
2. **Демаска тем же `payload_id`** — повторный запрос с маскированным текстом возвращает
   оригинал.
3. **Ловушки** — «поэт Александр Пушкин» и «Отделение банка: …» не маскируются
   (публичное лицо / адрес отделения — не ПД).
4. **Вариации форматов** — паспорт, телефон и карта в разных написаниях (разделители,
   без кода страны, с/без слова-маркера) маскируются корректно.
5. **Политика системы** — заголовок `X-System-Id`: `support-bot` (без демаскирования),
   `secure-vault` (контекстное маскирование), отключённая `legacy-crm` → HTTP 403.
6. **Логи и метрики** — в логах только типы ПД и счётчики (без текста); `GET /metrics`
   отдаёт latency, requests и tokens.
7. **Демо-прокси** — `POST /demo/llm`: в LLM уходит текст с `[FIO_1]`, ответ
   детокенизируется обратно.

## Производительность

Реальные замеры на горячем пути (без LLM):

- короткий запрос — ~0,2 мс на движок;
- ~100k токенов (~670 тыс. символов) — ~0,8 с;
- плотный текст с 35 000 спанов — < 3 с (фактически ~1,1 с).

Развёртывание: uvicorn **4 воркера** + Redis (общий стор соответствий между воркерами).

## Ограничения

Честно о границах:

- **regex-движок** не ловит имена вне словаря без маркеров-ключевых слов — для этого
  нужен `natasha`;
- **адрес** — эвристики, возможны пропуски нестандартных формулировок;
- **демо-прокси** в реальную LLM требует ключ AlfaGen в `.env`.
