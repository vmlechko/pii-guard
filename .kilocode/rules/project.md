# Правила проекта «Модуль безопасности ПД»

- Критерий готовности — `pytest -q` зелёный. Тесты описывают контракт, их не менять, менять код.
- Python 3.11, FastAPI, pydantic v2. Зависимости только из `requirements.txt`. Natasha — только в
  отдельном опциональном модуле, в основные зависимости не входит.
- Горячий путь `/process` никогда не обращается к LLM: идентификация локальная (regex + правила).
- Маскируется только значение ПД. Служебные слова («паспорт», «серия», «номер», «ул.», «д.», «кв.»,
  «Уважаемый», «Клиент») остаются как есть.
- Детекция — таблица правил и один цикл, а не функция с веткой на каждый тип. Сложность функции ≤ 10.
- Регэкспы собирать из коротких именованных фрагментов; ключевые слова — через общий хелпер.
- Не ловить `Exception` вслепую; никаких `try/except: pass`; никаких `verify=False`.
- В логах и метриках никогда нет исходного текста — только типы ПД и счётчики.
- Импорты наверху и отсортированы; аннотации типов `str | None`; pathlib вместо os.path.
- Комментарии и докстринги на русском, кратко: зачем, а не что.
- После каждой задачи запускать тесты и показать их вывод.
